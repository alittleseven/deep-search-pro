# Deep Search Pro 聊天页与 Trace 页重设计规格

日期：2026-08-21

## 1. 目标

为 Deep Search Pro 重建两个前端页面：

- `/`：以实际问答为中心的聊天主页。
- `/trace`：用于查看和诊断一次 Agent 运行过程的附带页面。

页面采用高级简约的石墨黑视觉风格。聊天页的信息架构参考 DeepSeek、豆包等成熟聊天产品的常用布局，但不复制其品牌元素。Trace 页采用纵向诊断结构，解决现有页面无法顺畅滚动、字体过小、信息拥挤和流程图空间不足的问题。

## 2. 范围边界

### 2.1 必须保持不变

- 不修改 Agent、RAGFlow、MySQL 或大模型调用逻辑。
- 不修改现有 API 路径、请求字段、响应结构或 WebSocket 协议。
- 不改变 Trace 状态推导语义。
- 不删除任何现有 Trace 功能。
- 不把未上报的 Agent 状态推断为已完成。

### 2.2 允许修改

- `web/` 下的 HTML、CSS 和 JavaScript 结构。
- 前端本地状态组织和浏览器会话记录。
- FastAPI 中仅用于返回聊天页、Trace 页和静态资源的路由。
- 与前端静态资源、路由和用户操作相关的测试。

### 2.3 不在本次范围内

- 服务端持久化聊天历史。
- 新增用户账户、权限或多租户能力。
- 修改 RAGFlow SDK 兼容逻辑。
- 修改数据库结构和测试数据。
- 增加新的后端搜索、取消任务或删除会话接口。

## 3. 现有接口映射

新前端必须继续覆盖以下接口：

| 接口 | 聊天页用途 | Trace 页用途 |
| --- | --- | --- |
| `POST /api/task` | 创建问答任务 | 重新运行当前问题 |
| `POST /api/upload` | 在提交任务前上传多个附件 | 在重新运行前上传附件 |
| `GET /api/files?path=...` | 展示回答关联的生成文件 | 展示“生成文件”页签 |
| `GET /api/download?path=...` | 下载回答关联文件 | 下载生成文件 |
| `GET /api/runs/{run_id}/trace` | 必要时恢复当前回答状态 | 加载完整 Trace 和分页事件 |
| `GET /api/threads/{thread_id}/runs` | 恢复浏览器保存的会话 | 查找线程中的运行记录 |
| `WS /ws/{thread_id}` | 接收运行状态和最终回答 | 实时更新事件、节点和指标 |

附件必须完成上传后才能调用 `POST /api/task`。聊天页和 Trace 页共享同一套 API 封装，避免产生两套协议实现。

## 4. 视觉系统

### 4.1 设计主题

- 主题：企业内部产品知识、库存和销售智能助手。
- 受众：需要频繁查询产品资料和运营数据的企业员工。
- 聊天页核心任务：快速提出问题并阅读可执行答案。
- Trace 页核心任务：快速判断运行是否正常，并定位具体节点或事件。

### 4.2 颜色

| Token | 色值 | 用途 |
| --- | --- | --- |
| Black | `#090B0C` | 流程画布和最深背景 |
| Canvas | `#111416` | 页面主背景 |
| Surface | `#171B1D` | 输入框、工具面板和节点 |
| Line | `#2A3033` | 分隔线和边框 |
| Text | `#F1F4F3` | 主文本 |
| Muted | `#899492` | 辅助文本 |
| Teal | `#43B8AD` | 主要操作、成功和已观测路径 |
| Amber | `#D4A65D` | 数据库来源和警告状态 |
| Red | `#E07870` | 失败和错误状态 |

禁止使用渐变背景、霓虹发光、大面积纯彩色、装饰性光球和无意义卡片堆叠。阴影仅用于输入框浮层和详情抽屉。

### 4.3 字体和密度

- 使用本地系统中文字体，不加载外部字体资源。
- 正文和表格主体为 `13-14px`。
- 按钮、标签和辅助信息不低于 `11px`。
- Trace 节点标题不低于 `13px`。
- 代码、ID 和原始事件使用 `Cascadia Mono, Consolas, monospace`。
- 不使用随视口宽度缩放的字体。

### 4.4 识别性元素

答案末尾设置低调的“回答依据”证据轨，用不同标记区分 MySQL、RAGFlow 和生成文件。该元素表达真实来源类型，不承担装饰作用。

## 5. 聊天主页 `/`

### 5.1 页面结构

- 左侧固定会话栏：品牌、新建对话、搜索、当前浏览器会话列表和连接状态。
- 顶部栏：当前会话标题、线程/运行标识、连接状态、复制线程 ID 和“运行详情”入口。
- 中央消息流：用户问题靠右显示，助手回答采用无气泡的宽阅读区。
- 底部固定输入区：多行输入、附件、上传状态和发送按钮。

桌面端消息正文最大宽度约为 `820px`。输入区与正文使用相同宽度和对齐线。移动端会话栏变为抽屉，输入区不能遮挡最后一条消息。

### 5.2 会话记录

后端没有全局聊天历史接口，因此左侧会话列表保存于当前浏览器 `localStorage`。每条记录至少包含：

- `thread_id`
- 最近一次 `run_id`
- 用户问题形成的标题
- 最近更新时间
- 当前状态

会话记录仅表示当前浏览器已知的线程。服务重启后，如果内存 Trace 已失效，页面保留线程标识并明确提示无法恢复，不展示虚假的历史回答。

### 5.3 提问流程

1. 用户输入问题并选择零个或多个附件。
2. 如果存在附件，先调用上传接口并显示上传状态。
3. 上传成功后调用任务接口。
4. 收到 `thread_id` 和 `run_id` 后建立 WebSocket。
5. 根据 Trace 事件显示当前处理状态。
6. 收到 `run_completed` 后渲染最终回答并刷新文件列表。
7. 收到 `run_failed` 或连接失败时，在当前消息位置显示可操作错误信息。

后端当前提供的是事件流和最终回答，不是 token 级文本流。前端不得模拟逐字输出。

### 5.4 回答展示

- 安全渲染 Markdown，不使用 `innerHTML` 注入内容。
- 支持标题、段落、列表、引用、代码块和表格。
- 回答操作包括复制和下载。
- 有生成文件时，在回答下方展示文件名、类型、大小和下载入口。
- 有可识别来源事件时显示回答依据；没有来源证据时不伪造来源条目。

### 5.5 页面状态

- 空状态：显示输入区和与当前项目数据相关的示例问题。
- 上传中：禁止重复发送，明确展示正在上传的文件。
- 启动中/运行中：显示最近一个活跃 Agent 或工具。
- 已完成：显示最终回答、证据和文件。
- 失败：显示后端错误摘要和重新运行入口。
- 断线：自动按现有策略重连，提示当前连接状态。

## 6. Trace 页面 `/trace`

### 6.1 信息架构

Trace 页采用可纵向滚动的诊断页面：

1. 顶部固定导航。
2. 运行标题、状态和指标。
3. 当前问题、附件和重新运行操作。
4. 全宽执行流程图。
5. 运行记录页签：实时事件、最终报告、生成文件、原始事件。

主内容区使用单一纵向滚动容器，不设置会阻止页面下滑的全屏固定面板。侧栏和顶部栏可以固定，但不能拦截主内容滚轮。

### 6.2 运行摘要

运行摘要继续展示：

- 运行状态
- 运行时间
- 事件数量
- 当前 Agent
- 工具调用数量
- 生成文件数量
- WebSocket/Trace 连接状态
- `thread_id` 和 `run_id`

当前问题可直接重新运行。上传附件仍遵循“先上传、后提交任务”的顺序。

### 6.3 真实流程图

流程图严格复用现有观测模型，不新增虚构 Agent：

- 节点：`input`、`main`、`network`、`database`、`knowledge`、`synthesis`、`files`、`output`。
- 连线：继续使用 `web/visualizer.js` 中定义的 11 条连接关系。
- 条件路径继续使用虚线。
- 已观测路径使用青绿色实线。
- `idle`、`active`、`completed`、`waiting`、`failed`、`unknown` 状态语义保持不变。

流程图获得完整内容宽度，并支持：

- 横向滚动以适应窄屏。
- 使用 `75%`、`100%`、`125%` 三档缩放，并提供适应画布控制。
- 点击节点选中。
- 键盘聚焦和激活节点。

缩放使用现有 DOM/SVG 和 CSS 实现，不引入新的流程图库。缩放后节点和连线必须保持同一坐标系。

### 6.4 节点详情抽屉

节点检查器不再常驻占用流程图宽度。点击节点后从流程图右侧打开抽屉，继续提供现有五类内容：

- Overview
- Input
- Output
- Event
- Error

抽屉内容可独立纵向滚动。用户可通过关闭按钮、遮罩或 `Escape` 关闭。抽屉关闭后焦点返回触发节点。

### 6.5 运行记录

流程图下方提供四个页签，完整保留现有功能：

- 实时事件：可滚动表格，展示时间、Agent/工具、事件、状态和消息；点击事件使用与节点相同的右侧详情抽屉。
- 最终报告：安全渲染最终 Markdown。
- 生成文件：展示文件元数据和下载按钮。
- 原始事件：展示 Trace 事件、WebSocket 消息和客户端错误 JSON。

实时事件增加前端搜索和状态筛选。筛选只作用于浏览器已加载的数据，不修改接口请求和事件存储。

## 7. 前端模块边界

保持原生 HTML、CSS 和 JavaScript，不引入 Vue、React 或新的构建链。

建议模块职责：

- `web/api.js`：继续作为所有 HTTP 和 WebSocket 协议入口。
- 共享会话模块：管理浏览器会话列表、当前线程和跨页面导航参数。
- 聊天状态模块：管理消息、附件、任务状态和最终回答。
- Trace 状态模块：继续管理事件去重、状态推导、恢复和角色映射。
- 流程图模块：继续管理真实节点、连线和选中状态，增加有限缩放和适应画布。
- 安全 Markdown 模块：供聊天回答和 Trace 最终报告共同使用。

模块之间通过普通数据对象和回调通信，不让视图代码直接拼接 API URL 或解释 Trace 协议。

## 8. 路由和跨页导航

- `/` 返回聊天主页。
- `/trace?thread_id=<id>&run_id=<id>` 返回 Trace 页面。
- 聊天页点击“运行详情”时携带当前线程和运行标识。
- Trace 页点击“返回问答”时恢复对应浏览器会话。
- URL 缺少参数时，Trace 页尝试使用本地保存的最近一次运行。
- 找不到运行时展示明确空状态，并提供返回聊天和重新运行入口。

FastAPI 的改动仅限静态页面路由和 favicon/资源响应，不得触碰任务执行逻辑。

## 9. 错误处理

- 上传失败：保留已选附件，允许重试，不提交任务。
- 任务创建失败：保留问题和附件信息，展示后端错误摘要。
- WebSocket 断开：使用现有指数退避策略重连，并从 `after_sequence` 恢复。
- Trace 已过期：保留线程 ID，说明内存记录不可用，提供重新运行。
- 文件列表失败：不影响最终回答，文件区域显示独立错误。
- 文件下载失败：保持当前页面，不清空运行状态。
- Markdown 或原始数据异常：以安全纯文本降级显示。

所有错误信息说明“发生了什么”和“可以执行什么操作”，不使用模糊提示。

## 10. 可访问性与响应式

- 所有图标按钮提供 `aria-label` 和 `title`。
- 所有交互元素支持键盘操作，并有可见焦点样式。
- 状态变化通过现有实时区域或等效 `aria-live` 区域播报。
- 尊重 `prefers-reduced-motion`。
- 桌面端、平板和手机均不得出现文本重叠。
- 小屏流程图允许横向滚动，不强制把节点缩小到不可读。
- 小屏事件表允许横向滚动或切换为事件列表。
- 输入区、抽屉和固定栏不得阻挡页面主要内容。

## 11. 测试与验收

### 11.1 自动测试

- `/`、`/trace`、CSS、JavaScript 和 favicon 返回正确状态及 MIME。
- HTML 不依赖外部运行时或外部字体。
- 页面不使用不安全 HTML 注入 sink。
- 附件上传完成后才创建任务。
- WebSocket URL 保持 `run_id` 和 `after_sequence` 参数。
- Trace 恢复保持事件去重和顺序。
- 会话列表序列化失败时安全降级。
- 现有节点状态和 11 条连线定义保持不变。

### 11.2 浏览器验收

- 桌面 `1440x900` 和移动端视口均截图检查。
- 聊天页可提交真实问题、上传文件并收到最终回答。
- 生成文件可以下载。
- 聊天页可以进入当前运行的 Trace。
- Trace 主页面可以从顶部滚动到运行记录底部。
- 流程图可横向滚动、缩放和适应画布。
- 点击每类节点可打开详情抽屉并切换五个详情页签。
- 四个运行记录页签均可使用。
- 刷新页面后可以恢复当前线程和运行。
- 控制台无 JavaScript 错误，无元素重叠。

### 11.3 回归边界

执行项目全量测试。已知的远端 RAGFlow SDK `v0.24.0` 与服务端 `v0.27.0` 分页兼容失败不属于本次前端改造范围，前端改造不得扩大或掩盖该问题。

## 12. 设计验收基线

实现应以已确认的效果图为视觉基线：

- 聊天页：石墨黑会话侧栏、居中消息流、无气泡助手回答和底部输入区。
- Trace 页：纵向诊断结构、完整宽度流程图、按需详情抽屉和下方运行记录。
- 两页使用相同的颜色、字体、边框、状态和间距规则。
- 视觉调整可以为真实数据长度和响应式布局做必要适配，但不得恢复为原有拥挤三栏结构。
